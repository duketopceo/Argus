# argus-reviewer eval — 2026-11-15 (the same four phases, after four fixes)

Suite: `evals/demo-suite`, the same 7 tasks (`01` to `06` and `07b`) on `evals/demo-app`
Harness: `evals/run-phases.mjs` (unchanged) · Raw results: `evals/results/2026-11-15-phases.json` (+ `.jsonl`) · Folded numbers: `evals/results/2026-11-15-summary.json` (`node evals/summarize-phases.mjs evals/results/2026-11-15-phases.json`)
Baseline: `docs/evals/2026-11-14.md` (the headline set there excludes the withdrawn `07-empty-cart-guard`; this run never included it, so both sides are the same 7 tasks)
Spend: $0.9691 against a $1.50 hard cap, one OpenRouter key through `orch`, passed by environment only

This run changes the code, not the method. Same 4 phases (cold, cached replay, drift heal, replay after heal), 5 replicates, the same 5 models each as its own escalation target, 700 task-runs, every run recorded, nothing retried. 337 of 700 failed (363 passed; 380 failed the previous time).

**Result in one paragraph.** One of the four fixes moved the numbers a lot: `openai/gpt-4.1-mini` can now ground (HTTP 400 on every call before; now 14/35 cold and 28/35 after a heal). `claude-haiku-4.5` is still 140/140, so the fixes cost it nothing and cached replay is still $0 and zero calls. The heal-correctness fix did not lift `gemini-2.5-flash`: healed task-runs that pass went from 16/30 to 11/20 (53% to 55%), while overall pass rates stayed within noise (cold 25 to 24, drift 21 to 20, of 35). It did change what failure looks like: 8 task-runs now fail at the heal step with a clear message instead of carrying a wrong heal forward. `gemini-2.5-flash-lite` is lower on drift (14/35 to 5/35) for two reasons set out below; this is a regression to read, not hide. `qwen3-vl` is unchanged at 5/35 (it never returns usable coordinates).

## What changed in the code

| # | Bug | Fix | Tests |
| - | --- | --- | ----- |
| 1 | A heal was accepted when the element under the point shared a word with the instruction, so a container whose text includes the label passed and the wrong fingerprint was saved | `Engine.locate` now checks a heal against the recorded element: accessible-name identity (`snippetsIdentityMatch`: shared words, and a name more than three times longer is a container and is rejected). On mismatch it re-asks the model with the recorded name as feedback, up to two corrections (bounded), then fails the step: `heal grounded to "X", which is not the element recorded for this step ("Y"); the healed fingerprint was not saved`. After the click, `TdSession` also compares the page before and after; a healed click with no change in the accessibility tree or pixels is not persisted (the previous record is kept, marked stale) and the heal event is withdrawn from write-back. | `tests/unit/heal-grounding.test.ts`: identity cases, a heal onto a container is corrected, a heal that never finds the element fails and saves nothing |
| 2 | Label-based inputs never ground (snippet was `aria-label` or text content only) | The snippet is the accessible name of the nearest interactive element under the point: `aria-label`, `aria-labelledby`, `<label for>`, `placeholder`, `title`, input button value, then text | `heal-grounding.test.ts` grounds `<label for>` input to `Full name` and a click on a span inside a button to the button |
| 3 | `gpt-4.1-mini` HTTP 400 on every grounding call (`x` missing from `required`) | `action` and `explore-action` schemas built by `strictObjectSchema`: every property required, optional ones nullable (`["number","null"]`), `additionalProperties: false`. The parsers already treat `null` as absent | `heal-grounding.test.ts` asserts both schemas; `prompts.test.ts` updated; the measured run below is the end-to-end check on four other providers |
| 4 | `if (!ok)` after `td.assert` never fired (the result object is always truthy) | `evals/suite/*` and the `argus-reviewer init` scaffold (and its goldens) check `result.verdict !== 'pass'` | `tests/unit/suite-assert-checks.test.ts` runs every suite file against a stub `td`: each test throws on a failing verdict and passes on a passing one |

Typecheck, lint and build are clean. `npm test` passes 1596 of 1597; the one failure, `action-contract.test.ts`, matches the checkout directory against `Argus/dist/cli.js` and fails in any worktree not named `Argus`; it is unrelated to these changes.

## What still fails

1. **A bad cold recording poisons the heal check, and the check cannot tell.** The identity check compares the healed element to what was recorded. If the cold run recorded a container (a model clicked a panel whose text contains the label, and the loose instruction match accepted it), replay and heal then compare against the container's text. Examples from this run: recorded `"Product Field notebook, $12.00 Add to cart Cart: 0 items …"`, heal found the real `Add to cart` button and was rejected as "not the recorded element" (`gpt-4.1-mini`, task 04). This is why 8 task-runs failed at a heal and why `flash` and `flash-lite` lost a few passes: the check is right about the heal and wrong about what it was compared to. All 8 rejections come from recordings made by the cold or replay phase (warm 6, drift 2). The cold grounding needs the same container test (a non-interactive element whose text is far longer than the quoted label is not the element the instruction names); the unit-tested `snippetsIdentityMatch` is reusable for it. Not done here because it needs its own remeasurement and the remaining budget would not cover a full second run of all models.
2. **Heals on cheap models still end in failed assertions.** `gemini-2.5-flash` heals 46 steps and 11 of 20 healed task-runs pass. Its drift failures are tasks 02 (5 of 5), 04 (5 of 5) and 05 (4 of 5), the same tasks as before. The identity check cannot see "right element, click did not toggle the state".
3. **`gemini-2.5-flash-lite` drift fell from 14/35 to 5/35.** Two causes, not one: 4 task-runs hit an OpenRouter rate limit (drift 05, 06, 07b and replay-after-heal 01, recorded as failures), and in the baseline most of its drift passes came from tasks that failed cold and re-grounded on the drifted page, an effect the 2026-11-14 doc already flagged. Task 05's cold toggle grounding works on the drifted layout and the identity check now sometimes blocks it. Conditional heal passes are 0/3, too few to read.
4. **`qwen3-vl-235b` returns no usable coordinates** (100 of its 120 failures are wrong-element, all 30 in the drift phase). The schema change does not help it; it needs a different prompt or a specialist grounding model.
5. **Assertions still lean on the screenshot** over the accessibility tree (not changed here).
6. **The demo app still sets `aria-label` on its inputs**, as in 2026-11-14, so this run measures the same page. The label fix is covered by a unit test on a real `<label for>` input, not by this eval.

## Method notes and caveats

- Same method, one allowed difference: the baseline folded two raw files (`…-phases.json` with the withdrawn `07` v1, and `…-07b.json`); this run is one file with the seven final tasks. Rows are not filtered.
- Each model ran in order flash-lite, gpt-4.1-mini, flash, qwen, haiku, 2 jobs at a time. `qwen3-vl` timeouts did not recur.
- Cost is the provider's per-call `usage.cost` summed by Argus's ledger, not a bill reconciliation.
- `n` is 35 per cell. Changes of a few passes (gemini-2.5-flash cold 25 to 24, drift 21 to 20) are inside noise; the `gpt-4.1-mini` change (5 to 14 cold, 5 to 28 after heal) is not.
- The no-effect check on a healed click is not exercised by this eval's counters; no run reports it.
- Whether the container-aware cold grounding recovers `flash`/`flash-lite` is a hypothesis, not a result.
